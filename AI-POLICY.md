## Introduction

In general, the more important the code/closer to the core of the library, the less likely we are to accept anything generated or assisted by AI.  We will continue to reevaluate this stance as AI/LLM gets better, but for now the following is our policy.  We do not accept any vibecoded code at all.  AI-assisted development **may** be acceptable in some circumstances.

Even where we allow the use of AI-generated or AI-assisted content, everything is reviewed by a human and tested manually.

## Where AI Assistance is Used

- modification of existing CMake configuration.
  - E.g. support for more feature gates and OS/compiler combinations.
- modification of existing of GitHub CI configuration.
  - E.g. support for more OS/compiler combination testing and OS-specific flags.
- adding additional test code based on existing test code, as AI does not do a good job writing test code from scratch.
- creation of prototypes for testing ideas. AI is **very** useful here.
- checking/updating documentation (though AI consistently mis-formats Markdown).
- checking for specific patterns in code that we want to refactor.
- updating comments.

## Where AI is Not Used

- Core library code. Our experiments using AI so far have not proven to give good results on the library code.

## Use of Contributed AI-Generated Content

- all PRs to core library C code need to come with a note stating that they are not generated by AI.  This is obviously something someone can lie about but AI code still tends to be fairly obvious if you have enough of it.
- AI generated code **may** be accepted for things that we already use it for (see above).
- We will generally refuse AI-generated bug reports.  Our experience using AI for this has been very negative.  AI can halucinate bugs because code does not match its training data, not because it is necessarily bad.  Sometimes it does find bugs but they need to be verified.  AI can lose context and thus enforced invariants on values.  It finds too many false positives.

## Git Commits Attributed to AI

Take any commits that say they came from Claude with suspicion.  Claude has a tendency to check things into Git even when we tell it not to in CLAUDE.md and AGENTS.md.  It also sometimes catches other files in the commit that it did not change or for which it decided to suggest a "fix" (this is one of the reasons AI is not good at debugging yet).  We are getting better at catching these, but some have been missed.

## Ownership of AI Code

The legal battles over ownership/copyright of AI-generated code continue.  Even if AI generated code is good, we will not accept AI-generated code in the core library until the legal questions are answered.

## Final Word

AI is just not ready yet.  In our experience it is not good enough to actually help with core coding where correctness and deep understanding matters AI-generated code that is critical requires more time doing oversight, review and testing than it saves.  AI-assisted coding is useful in some circumstances but not vibecoding.
